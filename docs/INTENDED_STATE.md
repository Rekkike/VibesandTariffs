Port Call Cost Analyzer — Intended State (three-port edition, v0.2.55)

This document is the historical audit concordance of the project's intended
state. It began as the Gothenburg-only pilot's authority of record (the
original preamble claimed sole authority over the repository); since v0.2.17
the repository carries three ports, and since v0.2.32 the committed
specification (`docs/SPECIFICATION.md`) is the sole governing authority for
the architecture, data model, engine, and UI contracts. This document now
serves as the audit-trail record: it states the intended structure of the
repository and the verification checkpoints that the test suite pins. Where
this document and the specification overlap, **the specification governs**;
the figures recorded here remain as historical checkpoints (they are pinned
by tests as literal expectations, and the per-port extraction references in
`docs/sources/` are the per-tariff audit records).

Rules: exactly one canonical YAML file per port; no JSON/YAML duplicates of
port data in the repository (`ports.json` is a gitignored build artifact,
regenerated byte-identically). Every source_reference in a data file points
to a document in `docs/sources/` or an explicit not-archived marker carrying
a live upstream URL. The PDFs are never modified. The version guard
(`core/scripts/check_spec_version.js`, wired to CI via
`.github/workflows/spec-guard.yml`) fails any change to behavior paths
(`core/src/`, `core/data/`, `core/scripts/`, `web/src/`) that does not add a
new specification changelog row in the same change.

## 2. Ports

Three ports are live, each with its own canonical data file, extraction
reference, and per-port workspace page; a cross-port comparison view (a
presentation over multiple single-port computations, never a separate
calculation path) prices one identical call at any subset of them:

- **Gothenburg 2026** (`gothenburg_2026.yaml`): the original pilot. Billers:
  Port of Gothenburg (port authority), Sjöfartsverket (national), APM
  Terminals (terminal). Fee families include the progressive port-infrastructure
  dues, waste dues (origin-gated since v0.2.50), pilotage, terminal handling,
  security, storage, yard surcharges, and ancillary services.
- **Hamburg 2026** (`hamburg_2026.yaml`): HPA (port authority; composite
  port fee with GT and environmental components), Hafenfonds surcharge,
  HHLA Container Terminal Burchardstrasse and Eurogate Hamburg terminal
  tariffs (tonnage/berth dues, handling, security, storage; a
  terminal-operator selector switches the terminal-operator-dependent lines).
- **Helsingborg 2026** (`helsingborg_2026.yaml`): municipal port dues
  (per call/per unit — no lay-time berth charge), Sjöfartsverket national
  dues, port-security fee (ISSC-gated: a vessel without a valid ISSC pays
  double), port dues cargo (unitized container goods 625.00 SEK/unit),
  towage, and yard services.

The complete fee inventory per port, with every rate and its verbatim
tariff citation, lives in each port's extraction reference under
`docs/sources/` — those are the per-tariff audit records this document
points to rather than duplicating.

## 3. Input Model (Intended)

- CSI class: A, B, C, D, E, Not registered. Not registered = E rates
  (Sjöfartsverket), no environmental discount (port dues).
- ESI score: numeric, plus "no score" state (no discount; base dues).
- NT: first-class input driving all Sjöfartsverket classes, with estimate
  fallback and "estimated" badge.
- Cargo flows: loaded/discharged ≤ 20 ft and > 20 ft, transshipped units,
  transit cargo; high/low-value tonnage split for godsavgift.
- Lay-up days; hours at berth; calls this month (frequency discounts);
  pilotage required/hours/lead time/extra pilot; arrival origin
  (v0.2.50: the waste-dues dimension, replacing flag gating);
  ISSC validity (v0.2.53 explicit three-state contract at Helsingborg);
  terminal operator and gangway class (Hamburg).
- The default call is the Maren Maersk profile (v0.2.48): worst-case
  published-rate call, no environmental discount unless explicitly entered.

## 4. Engine Behavior (Intended)

1. Results group by biller, then into three per-port segments derived from
   fee_family: Vessel Call, Energy at Berth, Yard & Storage. (The
   comparison view additionally groups by the v0.2.52 operational stages —
   a comparison-view presentation layer; the per-port segments stand.)
2. The Sjöfartsverket block presents its components as visible lines
   (vessel fee, readiness fee, cargo fee, pilotage, ordering fee).
3. No fee line may silently disappear; absence renders explicitly
   ("not levied at this port" in the comparison view since v0.2.52).
4. Progressive calculations are progressive (each GT/NT portion at its band
   rate), never banded-uniform.
5. Discounts compose per tariff semantics (port environmental discount on
   infrastructure dues; Sjöfartsverket frequency discount on vessel +
   readiness fees only).
6. Least-favourable honesty (spec 4.4.2): a blank conditional input prices
   the least favourable variant with a visible fallback flag — never
   silently (the v0.2.53 ISSC contract is the worked example).
7. Every rule carries a source_reference; a data rule the engine does not
   recognize is skipped with a visible warning, never silently matched
   (the v0.2.50/0.2.53 flag_state and issc_valid guards).

## 6. Reporting Protocol

Completion reports state verifiably: commit SHA, the canonical file paths,
and the CI/deployment conclusions. A report is true only if every stated
fact is checkable on GitHub. Do not report predictions or intentions as
accomplishments. Deployment claims cite the served artifact, never the
pipeline exit status alone — the deployment record (SHA and timestamp from
the repository's deployment history) and a content marker of the deployed
bundle matching the reported commit (the specification's section 8 carries
the current, authoritative protocol: cache-bypass fetch of the served HTML,
bundle identity via the CRA content-hash filename match between the local
zero-warning build and the deploy log's artifact listing, authoritative
spec at raw.githubusercontent at the delivered SHA). A green run that
deployed nothing is a false report.
