## Unit 1 — Design brief (mockup level; nothing enters the repository)

### 1.1 What the current design is, honestly

A dense, calm, data-forward "financial ledger" (index.css header calls it IBM Carbon conventions, implemented natively): 4px spacing scale, 5-step type scale, tabular numerals, right-aligned figures, dark default with a light remap over identical token names, honesty-first wording throughout. It is trustworthy by construction — that is its strength and the constraint on any overhaul.

Concrete stock/rough edges observed at e09b484 (each a named pain point, fixed one by one in 1.3):

1. **One "Ports" control carries two jobs.** Navigation and compare-selection live only inside the drawer; with it closed, the compare state shows only as "Comparing 4/6" in the toggle summary. (The tab-bar predecessor's overflow/scroll problems are recorded in `docs/EXPANSION_AUDIT.md:79`; the v0.5.0 drawer improved on them but kept the dual role.)
2. **The header Print button silently navigates** to the comparison when pressed on a workspace page — an undisclosed side effect of a button labeled "Print / Save as PDF".
3. **Two h1 headers stack on the comparison page** — the app header ("Port Call Cost Analyzer") and the view's own header Paper ("Port Comparison").
4. **The theme toggle is a stock text button** ("☀ Dark"/"☾ Light"); `theme-color` meta is the stale CRA-era `#1976d2`; the declared IBM Plex Sans is never loaded, so the UI renders in the fallback system stack.
5. **Cell density on the comparison table**: every figure cell can carry native amount + flag badge + converted secondary + per-GT annotation + OPS fold + per-line details — honest but visually heavy; desktop shows conversions inline while mobile hides them behind a disclosure (asymmetric).
6. **Workspace layout**: 50/50 inputs/results grid below md; the results column requires scrolling; the zero-line disclosure and segment toggles are small controls above a long list.
7. **Chevron transitions are hardcoded** `150ms` with no `prefers-reduced-motion` handling.

### 1.2 Target design direction — "calm ledger, modernized chrome"

Keep the honesty architecture exactly (tabular figures, right-aligned amounts, citations at line level, explicit-absence cells); modernize everything around it:

- **Visual language.** Typography: either self-host IBM Plex Sans woff2 under `web/public/` (offline-honest, no runtime CDN) or commit to a high-quality system stack and delete the dead declaration — a ruling point (1.5 D2). Type scale grows one step (title 22px, display 28px kept), tighter letter-spacing on headings. Color: keep the two-palette token model (dark default, light remap over identical names) but refine values for AA contrast, add an elevation scale (3 shadow levels), a radius scale (6/10/14px), tint pairs for every semantic color, an on-accent text color, and a `color-scheme` per mode (already present). Accent: a slightly desaturated port-blue in dark, deep signal blue in light; positive/warning/error keep their tint+badge pattern. Spacing: keep the 4px scale; introduce an optional density multiplier (the mockup carries `--density`) so "more spacious" is a token, not a rewrite. Density default stays at today's — the app's job is comparison at a glance.
- **Component-styling approach — recommendation: design tokens as the single source, consumed by both layers.** Three options weighed against the MUI 5 substrate:
  1. *MUI theme customization only* — rejected: the app's real surface is the 1 982-line custom CSS layer; MUI components (Paper, Grid, Table, TextField, Checkbox, ToggleButton, Dialog) are the minority. Theme-only would leave the two systems drifting (already observed: stale `theme-color`).
  2. *CSS layer only* — workable but leaves MUI components on the stock bridge and the drift permanent.
  3. **Tokens module + CSS + MUI bridge (recommended):** a new `web/src/designTokens.ts` exporting the palette/token map for both modes; `appTheme.muiThemeFor` consumes it (MUI palette, breakpoints, typography, shape from the same source); `index.css` keeps its `:root` blocks (preserving the v0.2.51 token discipline — every color literal inside the token blocks, extended so the tokens module is the pinned mirror with a test, as `summaryTheme.test.ts` already pins token discipline). No CSS-in-JS migration; MUI 5 + emotion stays. Queued majors (§2.6) do not ride.
- **Navigation / IA fixes, one by one:** (P1) persistent top navigation — a segmented port control plus a "Compare ports" entry, with the compare selection always visible as an `n/6` chip that opens a country-grouped selection popover (the drawer's grouping and cap logic carry over unchanged); the drawer retires. (P2) Print control keeps its header place; on workspace pages it is labeled "Print comparison" and still routes through the comparison (behavior unchanged, disclosure by label). (P3) the comparison view's duplicate header Paper is removed; "Port Comparison" becomes an h2 in the content area — one h1 per page. (P4) theme toggle becomes an icon button (sun/moon) with `aria-label`, and `theme-color` follows the mode from JS. (P5) comparison cells get a quieter secondary style (one line, smaller, `text-3`) with the converted tag; line-level detail stays behind the existing expandable rows. (P6) workspace: total strip becomes sticky at the top of the results column; input cards get consistent radii/elevation. (P7) all transitions honor `prefers-reduced-motion`.
- **Responsive:** contract constants unchanged (360 px floor, 600 px stacking, transposed cards — never horizontal scroll); add a mid breakpoint so the workspace grid collapses below ~900 px instead of MUI md; the `__setMobileQueryForTests` seam and `responsive.test.ts` constants stay.
- **Accessibility:** the pinned WCAG 2.2 AA floor (`accessibility.test.ts`) carries over; new palettes are AA-checked in the stage gate report; every new control gets a role/label/keyboard path; focus-visible policy unchanged; reduced-motion added.
- **Mockup:** `/tmp/pcca-consult/mockup/index.html` — a static scratch render of the proposed tokens (light + dark via `data-theme`), persistent nav with visible compare chip, sticky total strip, and a comparison table that keeps the honest cells verbatim (incl. "no published rate in the archived record at this port"). Scratch only.

### 1.3 What does not change (carried verbatim through any redesign)

The full honesty inventory of §0.3, the fail-closed input contract, provenance/trust surfaces, zero core/ and zero figure movement, print parity (paper header disclosures + both break-inside properties), and the recorded-not-encoded doctrine (1,029 / 453 never rendered).
